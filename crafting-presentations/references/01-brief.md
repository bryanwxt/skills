# Phase 1: Brief

The brief is a short statement of **who**, **what they should be able to do afterwards**, and **the one question the presentation answers**. Every later decision gets checked against it.

## What to find out

The first five are required. Ask only about gaps the request doesn't already fill, and reflect back what the user already told you instead of asking it again. Ask **all the brief questions in one message, at most 5**. Give each one a **recommended default**, so "looks good" is a complete answer. If an answer changes the type or the scale, say so and re-classify.

1. **Audience.** Who exactly, and what do they already know and believe about this? Are there decision-makers, skeptics, or mixed levels in the room?
   - Decide/Inform/Talk: what is their current position? Pick one of the seven reader positions below.
   - Teach: name 1–3 learner personas, one line each (who they are, what they know, what they want). Phase 2 expands them into the full five-part template.
2. **Outcome.** After the session, the audience will be able to ___. For Decide, name the decision and who makes it. For Teach, name what learners will be able to *do*.
3. **The one question** in the audience's head that the presentation answers. There is only one. "Should we, and if so how?" becomes "How?"
4. **Constraints.** Time slot, including time for Q&A. The medium: in-room, remote, read later as a pre-read, or recorded. The format wanted (pptx, Google Slides, web, Markdown). House template. Hard deadline.
5. **Material.** What evidence, data, and examples exist, and what is claimed but not yet shown. For example, the user says "I think the cause is X": what supports that?
6. *(Optional)* Politics: who has to be pre-wired, and what history would make someone defensive.
7. *(Optional, Teach)* Setup and logistics: the learners' machines and tools, whether helpers are available, class size.

## Reader positions (Decide/Inform/Talk)

Pin down R1, the current undesired result, and R2, the desired result, stated measurably. Then work out which position the audience is in. That position sets the Question.

| Audience position | Their Question |
|---|---|
| Doesn't know how to get from R1 to R2 | What should we do? |
| Has a solution in mind, unsure it's right | Is it the right solution? |
| Knows the solution | How do we implement it? |
| Tried a solution that failed | Why didn't it work / what now? |
| Has several options | Which one? |
| Knows R1 but can't state R2 | What should our objective be? |
| Knows R2, unsure whether they're at R1 | Do we have a problem? |

If the user talks about "alternatives", R2 is usually still vague, so define R2 first.

**Mixed audience** (a board, or a cross-functional room): pick the position of **whoever makes the decision**. Then list the other positions as anticipated objections to answer in the support or appendix.

## The brief

Use `assets/brief-template.md`. In the brief, separate **what the user said** from **what you assumed**. Assumptions get tagged `[ASSUMED]` so the user can correct them in one pass.

**If a missing fact *is* the answer** (e.g. "is the new site fixed?" with no current numbers), it has no default. Ask for it explicitly at the brief gate. If it's still missing, storyline both outcomes: the governing thought for each, and how the type changes (e.g. "not fixed" turns Inform into Decide).

**Other evidence gaps are findings, not blockers.** List them in the brief with a proposed way to close each one, such as "pull refund reasons from the support tool to confirm the carrier hypothesis". Carry on, and put `[NEEDS DATA: …]` placeholders in later phases. Never invent numbers.

**Gate:** show the brief and ask "Does this match what you're after?" Move to Phase 2 on a yes, or on corrections you then fold in.
