# Glossary

> Cross-cutting file for Greg Wilson, *Teaching Tech Together* (2018), CC BY 4.0. Entries marked "book glossary" are reproduced verbatim from the book's Glossary appendix. The others are terms the chapter files define that the book's glossary lacks, condensed by the reference readers; the file column says where each is developed.

| Term | Meaning | Source |
|---|---|---|
| 2×2 feedback grid | Went well / can improve crossed with content / presentation. | `08` |
| Absolute beginner | Someone who has never encountered concepts or material before. The term is used in distinction to false beginner. | book glossary |
| Accumulator pattern | Repeatedly fold a collection's items into one result variable. | `04` |
| ADEPT | Introduce a concept via Analogy, Diagram, Example, Plain language, Technical details. | `05` |
| Agile development | An approach to software development that emphasizes short iterations, incremental delivery, and close collaboration between customers and developers. | book glossary |
| Authentic task | A task which contains important elements of things that learners would do in real (non-classroom situations). To be authentic, a task should require learners to construct their own answers rather than choose between provided answers, and to work with the same tools and data they would use in real life. | book glossary |
| Automaticity | The ability to do a task without concentrating on its low-level details. | book glossary |
| Backward design | An instructional design method that works backwards from a summative assessment to formative assessments and thence to lesson content. | book glossary |
| Behaviorism | A theory of learning whose central principle is stimulus and response, and whose goal is to explain behavior without recourse to internal mental states or other unobservables. See also cognitivism. | book glossary |
| Blank screen of terror | Novice paralysis facing an empty editor. | `12` |
| Bloom’s Taxonomy | A six-part hierarchical classification of understand whose levels are knowledge, comprehension, application, analysis, synthesis, and evaluation that has been widely adopted. See also Fink’s Taxonomy. | book glossary |
| Branch coverage | The degree to which a set of tests exercise all possible branches of control structures like if/else statements. | book glossary |
| Brand | The associations people have with a product’s name or identity. | book glossary |
| Calibrated peer review | Having students compare their reviews of sample work with an instructor’s reviews before being allowed to review their peers’ work. | book glossary |
| Change pattern | A named tactic for introducing ideas in organizations [Mann2015]. | `15` |
| Choral explanations | Many answers per question, each suiting a different learner (Caulfield). | `06` |
| Chunking | The act of grouping related concepts together so that they can be stored and processed as a single unit. | book glossary |
| cMOOC / xMOOC | Connectivist, distributed MOOC vs. centralized, instructor-driven MOOC. | `11` |
| Co-opetition | An open contest mixing collaboration and competition. | `11` |
| Co-teaching | Teaching with another instructor in the classroom. | book glossary |
| Code & Run (C&R) | Write code that produces a specified output. | `12` |
| Cognitive apprenticeship | A theory of learning that emphasizes the process of a master passing on skills and insights situationally to an apprentice. | book glossary |
| Cognitive Load Theory | Cognitive load is the amount of mental effort required to solve a problem. Cognitive load theory divides this effort into intrinsic, extraneous, and germane, and holds that people learn faster and better when extraneous load is reduced. | book glossary |
| Cognitivism | A theory of learning that holds that mental states and processes can and must be included in models of learning. See also behaviorism. | book glossary |
| Collective expert blind spot | An organization's shared inability to see as newcomers do. | `13` |
| Community of action / concern / interest / place | Communities built on a shared goal, problem, love, or proximity. | `13` |
| Community of practice | A self-perpetuating group of people who share and develop a craft such as knitters, musicians, or programmers. See also legitimate peripheral participation. | book glossary |
| Community representation | Using cultural capital to highlight students’ social identities, histories, and community networks in learning activities. | book glossary |
| Competent practitioner | Someone who can do normal tasks with normal effort under normal circumstances. See also novice and expert. | book glossary |
| Compliment sandwich | Positive, negative, positive feedback; tiresome when overused. | `08` |
| Computational integration | Using computing to re-implement pre-existing cultural artifacts, e.g., creating variants of traditional designs using computer drawing tools. | book glossary |
| Computational thinking | Thinking about problem-solving in ways inspired by programming (though the term is used in many other ways). | book glossary |
| Concept inventory | A validated MCQ instrument that pinpoints specific misconceptions. | `02` |
| Concept map | A picture of a mental model in which concepts are nodes in a graph and relationships are (labelled) arcs. | book glossary |
| Concrete-Representational-Abstract (CRA) | Objects, then pictures, then symbols; mainly for younger learners. | `06` |
| Connectivism | A theory of learning holds that knowledge is distributed, that learning is the process of navigating, growing, and pruning connections, and which emphasizes the social aspects of learning made possible by the Internet | book glossary |
| Constructivism | A theory of learning that views learners as actively constructing knowledge. | book glossary |
| Content knowledge | A person’s understanding of a subject. See also general pedagogical knowledge and pedagogical content knowledge. | book glossary |
| Contributing student pedagogy | Having students produce artifacts to contribute to other students’ learning. | book glossary |
| Conversational programmer | Someone who needs to know enough about computing to have a meaningful conversation with a programmer, but isn’t going to program themselves. | book glossary |
| CS0 | An introductory college-level course on computing aimed at non-majors with little or no prior experience of programming. | book glossary |
| CS1 | An introductory college-level computer science course, typically one semester long, that focuses on variables, loops, functions, and other basic mechanics. | book glossary |
| CS2 | A second college-level computer science course that typically introduces basic data structures such as stacks, queues, and dictionaries. | book glossary |
| Curb-cut effect | Accessibility fixes end up helping everyone. | `10` |
| Deficit model | The idea that some groups are under-represented in computing (or some other field) because their members lack some attribute or quality. | book glossary |
| Deliberate practice | The act of observing performance of a task while doing it in order to improve ability. | book glossary |
| Demonstration lesson | A staged lesson in which one teacher presents material to a class of actual students while other teachers observe in order to learn new teaching techniques. | book glossary |
| Diagnostic power | The degree to which a wrong answer to a question or exercise tells the instructor what misconceptions a particular learner has. | book glossary |
| Direct instruction | A teaching method centered around meticulous curriculum design delivered through prescribed script. | book glossary |
| Educational psychology | The study of how people learn. See also instructional design. | book glossary |
| Educationalization | Pushing social problems onto schools to solve [Laba2008]. | `15` |
| Ego depletion | The impairment of self control that occurs when it is exercised intensively or for long periods. | book glossary |
| Elevator pitch | A short description of an idea, project, product, or person that can be delivered and understood in just a few seconds. | book glossary |
| End-user programmer | Someone who does not consider themselves a programmer, but who nevertheless writes and debugs software, such as an artist creating complex macros for a drawing tool. | book glossary |
| End-user teacher | By analogy with end-user programmer, someone who is teaching frequently, but whose primary occupation is not teaching, who has little or no background in pedagogy, and who may work outside institutional classrooms. | book glossary |
| Episode | A teaching chunk between formative assessments; three to four per hour. | `06` |
| Expert | Someone who can diagnose and handle unusual situations, knows when the usual rules do not apply, and tends to recognize solutions rather than reasoning to them. See also competent practitioner and novice. | book glossary |
| Expert blind spot | The inability of experts to empathize with novices who are encountering concepts or practices for the first time. | book glossary |
| Expertise reversal effect | The way in which instruction that is effective for novices becomes ineffective for competent practitioners or experts. | book glossary |
| Externalized cognition | The use of graphical, physical, or verbal aids to augment thinking. | book glossary |
| Extrinsic motivation | Being driven by external rewards such as payment or fear of punishment. See also intrinsic motivation. | book glossary |
| Faded example | A series of examples in which a steadily increasing number of key steps are blanked out. See also scaffolding. | book glossary |
| False beginner | Someone who has studied a language before but is learning it again. False beginners start at the same point as true beginners (i.e., a pre-test will show the same proficiency) but can move much more quickly. | book glossary |
| Far Transfer | Transfer of learning or proficiency between widely-separated domains, e.g., improvement in math skills as a result of playing chess. | book glossary |
| Feedback translator | A third party who summarizes raw feedback for its recipient. | `08` |
| Fink’s Taxonomy | whose categories are foundational knowledge, application, integration, human dimension, caring, and learning how to learn. See also Bloom’s Taxonomy. | book glossary |
| Fixed mindset | The belief that an ability is innate, and that failure is due to a lack of some necessary attribute. See also growth mindset. | book glossary |
| Flipped classroom | One in which learners watch recorded lessons on their own time, while class time is used to work through problem sets and answer questions. | book glossary |
| Flow | The feeling of being fully immersed in an activity; frequently associated with high productivity. | book glossary |
| Fluid representation | The ability to move quickly between different models of a problem. | book glossary |
| Formative assessment | Assessment that takes place during a lesson in order to give both the learner and the instructor feedback on actual understanding. See also summative assessment. | book glossary |
| Foundational myth | An organization's 'once upon a time' origin story. | `14` |
| Free-range learner | Someone learning outside an institutional classrooms with required homework and mandated curriculum. (Those who use the term occasionally refer to students in classrooms as “battery-farmed learners”, but we don’t, because that would be rude.) | book glossary |
| Functional programming | A style of programming in which data structures cannot be modified once they have been created, and in which functions that operate on other functions are widely used for abstraction. | book glossary |
| Fuzz testing | A software testing technique based on generating and submitting random data. | book glossary |
| Geek gene | Folk belief in innate programmers; refuted by Patitsas. | `10` |
| General pedagogical knowledge | A person’s understanding of the general principles of teaching. See also content knowledge and pedagogical content knowledge. | book glossary |
| Glass's Law | Any new tool or practice initially slows you down. | `15` |
| Governance board / service board | Board that hires and oversees the director vs. board whose members also do the work. | `13` |
| Group signup | Registering for a workshop together with trusted peers. | `10` |
| Growth mindset | The belief that ability comes with practice. See also fixed mindset. | book glossary |
| Guided notes | Instructor-prepared notes that cue students to respond to key information in a lecture or discussion. | book glossary |
| Hashing | Generating a condensed pseudo-random digital key from data; any specific input produces the same output, but different inputs are highly likely to produce different outputs. | book glossary |
| Hypercorrection effect | The more strongly someone believed that their answer on a test was right, the more likely they are not to repeat the error once they discover that in fact they were wrong. | book glossary |
| Implementation science | The study of how to translate research findings to everyday clinical practice. | book glossary |
| Impostor syndrome | A feeling of insecurity about one’s accomplishments that manifests as a fear of being exposed as a fraud. | book glossary |
| Inclusivity | Working actively to include people with diverse backgrounds and needs. | book glossary |
| Inquiry-based learning | The practice of allowing learners to ask their own questions, set their own goals, and find their own path through a subject. | book glossary |
| Instructional design | The craft of creating and evaluating specific lessons for specific audiences. See also educational psychology. | book glossary |
| Interruption bingo | A grid tallying who interrupts whom in a meeting. | `13` |
| Intrinsic motivation | Being driven by enjoyment of a task or the satisfaction of doing it for its own sake. See also extrinsic motivation. | book glossary |
| Inverted Code & Run | Write tests that find a given code's bug. | `12` |
| Jugyokenkyu | Literally “lesson study”, a set of practices that includes having teachers routinely observe one another and discuss lessons to share knowledge and improve skills. | book glossary |
| Kirkpatrick levels | Reaction, learning, behavior, results: four levels for evaluating training. | `09` |
| Lateral knowledge transfer | The “accidental” transfer of knowledge that occurs when an instructor is teaching one thing, and the learner picks up another. | book glossary |
| Learned helplessness | A situation in which people who are repeatedly subjected to negative feedback that they have no way to escape learn not to even try to escape when they could. | book glossary |
| Learner persona | A brief description of a typical target learner for a lesson that includes their general background, what they already know, what they want to do, how the lesson will help them, and any special needs they might have. | book glossary |
| Learning objective | What a lesson is trying to achieve. | book glossary |
| Learning outcome | What a lesson actually achieves. | book glossary |
| Learning trajectory | A literature-derived beginner-to-advanced sequence of ideas. | `07` |
| Legitimate peripheral participation | Newcomers’ participation in simple, low-risk tasks that a community of practice recognizes as valid contributions. | book glossary |
| Live coding | The act of teaching programming by writing software in front of learners as the lesson progresses. | book glossary |
| Long-term memory | The part of memory that stores information for long periods of time. Long-term memory is very large, but slow. See also short-term memory. | book glossary |
| Marketing | The craft of seeing things from other people’s perspective, understanding their wants and needs, and finding ways to meet them | book glossary |
| Media computation | Teaching programming through manipulating images and sound; the top intervention in [Viha2014]. | `07` |
| Mental model | A simplified representation of the key elements and relationships of some problem domain that is good enough to support problem solving. | book glossary |
| Metacognition | Thinking about thinking. | book glossary |
| Minimal fix | The smallest change that makes buggy code correct. | `12` |
| Minute cards | A feedback technique in which learners spend a minute writing one positive thing about a lesson (e.g., one thing they’ve learned) and one negative thing (e.g., a question that still hasn’t been answered). | book glossary |
| Misconception types | Factual error, broken model, or fundamental (identity-linked) belief. | `02` |
| Near transfer | Transfer of learning or proficiency between closely-related domains, e.g., improvement in understanding of decimals as a result of doing exercises with fractions. | book glossary |
| Never a blank page | Novices always start exercises from existing code. | `09` |
| Notional machine | A general, simplified model of how a particular family of programs executes. | book glossary |
| Novice | Someone who has not yet built a usable mental model of a domain. See also competent practitioner and expert. | book glossary |
| One up, one down | Alternating positive and negative end-of-day feedback, no repeats. | `09` |
| Pair programming | A software development practice in which two programmers share one computer. One programmer (the driver) does the typing, while the other (the navigator) offers comments and suggestions in real time. Pair programming is often used as a teaching practice in programming classes. | book glossary |
| Parsons Problem | An assessment technique developed by Dale Parsons and others in which learners rearrange given material to construct a correct answer to a question. | book glossary |
| Pedagogical content knowledge | (PCK) The understanding of how to teach a particular subject, i.e., the best order in which to introduce topics and what examples to use. See also content knowledge and general pedagogical knowledge. | book glossary |
| Peer instruction | A teaching method in which an instructor poses a question and then students commit to a first answer, discuss answers with their peers, and commit to a (revised) answer. | book glossary |
| Persistent memory | see long-term memory. | book glossary |
| Personalized learning | Automatically tailoring lessons to meet the needs of individual students. | book glossary |
| Plausible distractor | A wrong or less-than-best answer to a multiple-choice question that looks like it could be right. See also diagnostic power. | book glossary |
| Positioning | What sets one brand apart from other, similar brands. | book glossary |
| Post mortem | End-of-project review producing Do Again / Do Differently items. | `13` |
| Preparatory privilege | The advantage of coming from a background that provides more preparation for a particular learning task than others. | book glossary |
| PRIMM | Predict, Run, Investigate, Modify, Make: a sequence for introducing code ideas. | `06` |
| Productive failure | Deliberately posing problems learners can't yet solve. | `10` |
| Programming plan | An expert pattern guiding how code is constructed. | `07` |
| Pull request | A set of proposed changes to a GitHub repository that can be reviewed, updated, and eventually merged. | book glossary |
| Question budget | A fixed rubric length; adding an item means removing one. | `08` |
| Rainfall Problem | Average integers read until a sentinel; a classic novice benchmark. | `07` |
| Read-cover-retrieve | A study practice in which the learner covers up key facts or terms during a first pass through material, then checks their recall on a second pass. | book glossary |
| Reflecting listening | The practice of paraphrasing a speaker’s point back to them immediately after hearing it in order to confirm understanding. | book glossary |
| Reflective practice | see deliberate practice. | book glossary |
| Reverse execution | Deduce the input that produced a given output or error. | `12` |
| Roles of variables | Eleven single-variable patterns giving novices a vocabulary for plans. | `07` |
| Scaffolding | Extra material provided to early-stage learners to help them solve problems. | book glossary |
| Self-determination theory | Intrinsic motivation comes from competence, autonomy, and relatedness. | `10` |
| Short-term memory | The part of memory that briefly stores information that can be directly accessed by consciousness. | book glossary |
| Situated learning | A model of learning that focuses on people’s transition from being newcomers to be accepted members of a community of practice. | book glossary |
| Social presence | The felt sense of being with others online. | `11` |
| Soup, then hymns | Deliver useful help before writing vision statements. | `13` |
| Split-attention effect | The decrease in learning that occurs when learners must divide their attention between multiple concurrent presentations of the same information (e.g., captions and a voiceover). | book glossary |
| Spoons | Metaphor for the limited daily energy of chronically ill people. | `10` |
| Status flags | Coloured sticky notes signalling 'done' or 'need help'. | `09` |
| Stereotype threat | A situation in which people feel that they are at risk of being held to stereotypes of their social group. | book glossary |
| Studio class | Immediate peer critique, where the teacher also critiques the critiques. | `08` |
| Subgoal labelling | Giving names to the steps in a step-by-step description of a problem-solving process. | book glossary |
| Summative assessment | Assessment that takes place at the end of a lesson to tell whether the desired learning has taken place. | book glossary |
| Superbug | The belief that the computer understands intent like a human. | `07` |
| Tangible artifact | Something a learner can work on whose state gives feedback about the learner’s progress and helps the learner diagnose mistakes. | book glossary |
| Teaching by contrast | Showing non-examples and what a technique won't solve. | `05` |
| Teaching commons | Lessons co-authored and maintained by a community, like open source. | `13` |
| Teaching to the test | Teaching aimed at passing externally set, high-stakes tests rather than learning. | `06` |
| Tells | Nervous habits that betray anxiety while teaching. | `08` |
| Test unlocking | Answer a question about a test before being allowed to run it. | `12` |
| Test-driven development | A software development practice in which programmers write tests first in order to give themselves concrete goals and clarify their understanding of what “done” looks like. | book glossary |
| Theme and variations | Make a small specified change to working code to alter its output. | `12` |
| Think-pair-share | A collaboration method in which each person thinks individually about a question or problem, then pairs with a partner to pool ideas, and then have one person from each pair present to the whole group. | book glossary |
| Throttling | Capping posts per learner so other voices fit. | `11` |
| Transfer-appropriate processing | The improvement in recall that occurs when practice uses activities similar to those used in testing. | book glossary |
| Tutorial vs manual | Model-building material for novices vs. gap-filling material for practitioners. | `02` |
| Twitch coding | Having a group of people decide moment by moment or line by line what to add to a program next. | book glossary |
| Two-stage exam | An individual exam immediately followed by the same exam in groups. | `05` |
| Understanding by design | see backward design. | book glossary |
| Unplugged | Teaching computing ideas without computers. | `07` |
| Working memory | see short-term memory. ## | book glossary |
